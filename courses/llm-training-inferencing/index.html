Part I · LLM training

1. Understand what LLM training changes and why

Outcome. Distinguish pretraining, continued pretraining, supervised fine-tuning, parameter-efficient adaptation, and preference- or reward-based post-training.
Recall first. What must a training system define besides model architecture: data, objective, update rule, evaluation, and checkpoint state?

Training adjusts model parameters so the model assigns higher probability to desired token sequences under a defined objective. A dataset becomes token IDs and masks; the model produces logits; a loss measures error; backward computes how the loss changes with each trainable parameter; and an optimizer turns those gradients into an update. Repeating this loop over many batches changes the model.

Pretraining learns general sequence patterns from a large corpus with a next-token objective. Continued pretraining uses the same broad objective on additional domain data. Supervised fine-tuning (SFT) trains on curated input-and-response examples, often masking prompt tokens so only selected response tokens contribute to loss. Parameter-efficient methods such as LoRA keep base weights frozen and train a much smaller set of adapter parameters.

Preference or reward-based post-training introduces another source of supervision. A system may compare candidate responses, score them with a reward function or model, and update the policy under constraints. GRPO is one such method discussed later. These stages are not interchangeable: they use different data, objectives, quality gates, memory profiles, and failure modes.

The course uses tiny models and short runs to expose mechanisms. They can prove that token masks, gradients, optimizer state, sharding, or serving logic behave as intended; they cannot establish production model quality or reproduce the data scale of foundation-model training.

Worked example

A base model can continue next-token training on domain text, then receive SFT on question-and-answer demonstrations. A LoRA SFT run changes only adapter weights. A later GRPO-style run generates groups of responses and uses relative rewards. Calling all three “fine-tuning” hides different objectives and state.

Check your reasoning

2. Turn text into a valid causal-language-model batch

Outcome. Trace text through tokenization, padding or packing, shifted labels, and a loss mask.
Recall first. For input tokens [A, B, C, D], which tokens are inputs and which are next-token targets in causal language modeling?

A tokenizer applies a defined normalization and segmentation algorithm to text. A token is one resulting text or byte piece. A token ID is the integer index assigned to that piece in a fixed vocabulary. The vocabulary is the lookup contract between IDs and pieces; it is not the model’s learned meaning. The model receives token IDs, not raw words.

An embedding table maps each token ID to a learned vector. Two identical IDs select the same row before context is applied. Position information is then combined with the sequence representation so the decoder can distinguish order. Special tokens, chat templates, truncation, padding side, and tokenizer revision are therefore part of the model input contract. Changing them can change IDs, sequence length, masks, and output even when the visible text looks similar.

Causal training predicts the next token at every selected position. The input sequence and target sequence are offset by one position: the hidden state after tokens through position t predicts the token at t+1. Padding targets and prompt targets that should not train the response can be replaced with -100, PyTorch cross-entropy's conventional ignore index. The count of unmasked target tokens—not the padded rectangle size—is the useful-token denominator for loss and throughput.

Padding forms rectangular batches by adding ignored positions. Packing joins examples into fewer fixed-length sequences to reduce padding waste. Packing must preserve example boundaries, position semantics, attention masks, and label masks; otherwise one example can attend to an unrelated example and silently change the objective. Record token-length distributions, padding fraction, and the fraction of tokens that contribute to loss.

Public-data licensing, consent, privacy, deduplication, and train/evaluation separation are prerequisites. The course uses synthetic or course-authored examples and does not treat lower training loss on them as model quality.

Worked example

Tokens [11,12,13,41,42,43] contain a three-token prompt followed by a three-token response. Inputs are positions 0–4 and next-token labels are positions 1–5. If the response begins with token 41, mask label positions that teach 12 and 13; keep labels that teach 41, 42, and 43. A padded final position is masked too.

Practice

Run Lab 13. Count trained and ignored targets by hand before execution. Explain why masked and unmasked losses can differ even though logits are identical, and why a lower one is not automatically better.

Check your reasoning

The mask changes which token errors are averaged; it does not change the forward logits. Loss values are comparable only with the same selected-token semantics. The lab's invariant is the trained/ignored count plus finite gradients, not a preferred numerical ordering of the two losses.

Review cue. Recount selected target tokens whenever packing, templates, truncation, or padding changes.

3. Trace a decoder-only transformer from embeddings to logits

Outcome. Explain embeddings, causal attention, MLPs, residual paths, normalization, logits, and next-token loss.
Recall first. Why can training process all positions of a known sequence in parallel while autoregressive decode cannot generate all future positions at once?

The embedding table converts each token ID into a hidden vector. Position information—commonly rotary position information in modern decoder models—makes order available to attention. The tensor now has shape [batch, sequence, hidden]. It is an activation created by the current batch; it is not another copy of the embedding parameters.

The model applies a stack of decoder blocks. Each block has two main transformations: causal self-attention mixes information from allowed earlier positions, and an MLP transforms each position through a wider intermediate representation. Normalization stabilizes the inputs to these transformations, while residual connections preserve and update the running hidden state. Repeating the block builds contextual representations progressively.

After the final block, a final normalization and language-model head produce one logit for every vocabulary entry at every position. Logits are unnormalized scores. During training, cross-entropy compares the selected position's logits with the shifted target ID. During inference, a decoding rule converts the final-position logits into the next token ID.

During training, the complete shifted sequence is known, so all positions can form attention queries simultaneously under the causal mask. During inference, token N+1 is unknown until token N has been selected; decode therefore contains a sequential loop even though each step uses parallel GPU kernels across layers, heads, and active sequences.

Worked example

For batch 4, sequence 256, hidden 512, the hidden state has shape [4,256,512]. With 8 heads, each head can use dimension 64. Queries, keys, and values become [4,8,256,64]. Attention returns the same head-shaped tensor, which is merged back to [4,256,512] before the output projection.

Practice

Check your reasoning

The QKV linear output is reshaped to batch, sequence, three projections, heads, and head dimension; unbinding selects Q/K/V; transposing places heads before sequence for SDPA; merging reverses that transformation. Cross-entropy compares final vocabulary logits with the next-token targets.

4. Follow data through attention, residual paths, and the MLP

Outcome. Explain what queries, keys, values, attention weights, residual connections, normalization, and the MLP contribute to one decoder block.
Recall first. Which component chooses information from earlier positions, and which component transforms each position independently?

Self-attention starts from the same hidden-state tensor and applies learned projections to create queries (Q), keys (K), and values (V). For each query position, dot products with allowed keys create compatibility scores. Scaling keeps score magnitudes manageable; the causal mask removes future positions; softmax turns the remaining scores into weights; and the weighted sum of value vectors produces an attention output.

Multi-head attention splits the hidden representation into several heads so different learned projections can form different relationships. The head outputs are concatenated and projected back to the model hidden size. Grouped-query attention uses more query heads than key/value heads. That changes projection and cache shapes but not the basic rule: queries decide what to read, keys participate in matching, and values carry the information that is mixed.

The MLP does not mix sequence positions. It expands each position into a wider intermediate representation, applies a nonlinear gated or activation function, and projects back to hidden size. Attention and MLP outputs are added to residual paths. Normalization keeps the scale presented to each transformation controlled. Removing or moving these pieces changes the architecture, not merely performance.

During training, the causal attention matrix for a sequence is conceptually triangular: every position can read itself and earlier positions. Efficient kernels do not need to materialize the full score matrix in HBM, but they must preserve the same semantics. This distinction becomes important when comparing a pedagogical attention implementation with PyTorch scaled-dot-product attention.

Worked example

For hidden size 512 and eight heads, each query head can use 64 features. With sequence length 256, Q, K, and V can be viewed as [batch, heads, 256, 64]. The attention result merges back to [batch, 256, 512]. An MLP might expand each 512-feature position to a wider intermediate size before projecting back.

Practice

Annotate CausalSelfAttention.forward in labs/tiny_lm.py. For every reshape, transpose, and matrix operation, write the input and output shape. Then identify where the causal mask is enforced and where the attention result rejoins the residual path.

Check your reasoning

Q/K/V split by head, attention compares sequence positions within each head, and the merged result returns to hidden size. The MLP keeps batch and sequence axes unchanged while transforming the feature axis. The causal mask belongs in attention-score semantics, not in the MLP.

Review cue. When later optimizing attention, state which semantic object is avoided or fused without changing the mask or output contract.

5. Follow the forward pass, backward pass, gradients, and optimizer step

Outcome. Explain what changes during one training step and distinguish a microbatch from an optimizer update.
Recall first. Which values persist after backward but before the optimizer step: activations, gradients, parameters, or Adam running statistics?

Forward applies the current parameters to a batch and produces logits. Cross-entropy turns the selected logits and target IDs into one scalar loss. Autograd records how the tensor operations are connected and retains the values needed to differentiate them. Calling backward() then applies the chain rule from the loss back through the language-model head, decoder blocks, and every trainable parameter.

A gradient says how sensitive the current batch loss is to a small change in one parameter; it is not itself the update. PyTorch accumulates gradients into each parameter’s .grad buffer. This makes gradient accumulation possible, but it also means stale gradients remain unless the training loop deliberately clears them. A normal update window is: clear gradients, run one or more forward/backward microbatches with correct loss scaling, optionally unscale and clip, run the optimizer, then advance the learning-rate schedule at its defined boundary.

AdamW transforms raw gradients using persistent first- and second-moment estimates, the learning rate, numerical stabilizers, and decoupled weight decay. The optimizer step changes parameters; the scheduler changes a future or current learning rate according to its contract. Gradient clipping bounds a chosen norm after all intended gradients are available, but it cannot repair a wrong target mask, non-finite activations, or a badly defined objective.

A microbatch is one forward/backward unit that creates an activation peak. Gradient accumulation performs several microbatches before one optimizer update. Effective global batch equals per-rank microbatch × accumulation steps × data-parallel ranks, adjusted for sequence/token weighting. Dividing each microbatch loss by the accumulation count is correct only when the microbatches contribute equal weighting; variable non-padding token counts may require a token-weighted numerator and denominator.

Worked example

Two ranks use microbatch 2 and accumulate four times. The effective example batch is 2 × 4 × 2 = 16. If each microbatch loss is a mean, divide each loss by four before backward (or equivalently scale gradients later) so the accumulated gradient matches one mean over the local accumulated batch before DDP averages gradients across ranks.

Practice

Run Labs 01 and 02. Verify the full-batch and accumulated gradients agree within tolerance. Record optimizer-update count separately from forward/backward microstep count and compute effective global tokens.

Check your reasoning

Agreement requires equal examples/tokens, model state, loss reduction, and gradient scaling. Accumulation reduces activation peak per microstep but increases the number of launches and delays the update. It does not reduce parameter or optimizer-state bytes.

Review cue. Whenever a training speed is reported, state whether the denominator is microsteps, optimizer steps, examples, or non-padding tokens.

6. Treat evaluation, checkpointing, and resuming as parts of training

Outcome. Design held-out evaluation, save complete state, and prove a resumed run follows the intended trajectory.
Recall first. Which states besides model weights can affect a resumed optimizer step?

Training loss shows fit to the optimization batch. Evaluation uses held-out data and frozen decoding or scoring rules to estimate transfer. Track token-weighted loss/perplexity carefully with masks, plus task-specific quality. Compare at equivalent token budgets and state which checkpoints were selected.

A resumable checkpoint may need model or adapter weights, optimizer state, scheduler position, global step/token counters, scaler state, RNG states, sampler position, and distributed/sharding metadata. Saving only weights supports fine-tuning from a point, not exact continuation. FSDP checkpoint formats can be sharded or consolidated; restoration must match the chosen contract.

Checkpoint I/O can pause both GPUs and stress shared storage. Measure save duration and frequency separately from steady training throughput. Use atomic or staged writes where the framework supports them, verify completion, and keep enough metadata to reject a partial or mismatched resume.

Worked example

A run saves weights at step 1,000 but omits optimizer moments and scheduler state. Reloading those weights with a fresh optimizer changes the next update and is not an exact resume. It may still be a valid new fine-tuning run if labeled that way.

Practice

Design a two-segment test: train N steps, save, reload in a fresh process, train M steps, and compare with an uninterrupted N+M control. Specify the equality or tolerance criterion, token order, and metadata that make the claim meaningful.

Check your reasoning

Exact deterministic equality may be unavailable for some distributed kernels, so predeclare acceptable loss/parameter tolerance and preserve seeds/data order. The checkpoint must include every state that influences the next update. A fresh-optimizer continuation is labeled as a new trajectory.

Review cue. Review checkpoint semantics before long runs; a file that cannot restore is not a training safety mechanism.

7. Perform supervised fine-tuning and understand LoRA’s savings

Outcome. Prepare masked instruction data, train LoRA adapters, and state which memory and checkpoint entries shrink.
Recall first. Does LoRA remove the need to store base-model weights and forward activations?

Supervised fine-tuning applies next-token training to curated prompt/response examples. Chat templates, end-of-sequence behavior, prompt masking, packing, truncation, data license, and evaluation must be explicit. Loss reduction on the training examples demonstrates optimization mechanics, not general usefulness.

LoRA freezes base weights and learns low-rank matrices on selected linear modules. Trainable parameters, gradients, optimizer state, and adapter checkpoint size fall substantially. Base weights still occupy memory and every forward/backward retains activations required by the adapted computation. Target-module selection and rank change both capacity and learning behavior.

Pin the public base model and tokenizer to the same immutable revision, disable unreviewed remote code, and record adapter configuration. Evaluate the adapter against a frozen baseline on held-out examples. Sharing an adapter requires the base-model identity and applicable licenses.

Worked example

A projection weight has shape [d_out,d_in]. A rank-r LoRA update represents it through matrices with roughly r(d_in+d_out) trainable values instead of d_in d_out. This reduces trainable state when r is small, but the frozen original matrix is still used in the forward pass.

Practice

Run Labs 05 and 13. Verify the trainable fraction, inspect target modules, and explain the label mask. Propose one held-out evaluation that could reject the adapter despite lower training loss.

Check your reasoning

The adapter saves trainable/optimizer/checkpoint state, not base weights or all activations. A valid rejection test uses held-out tasks or quality constraints and identical decoding, not the training loss alone. Incorrect templates or masking can create deceptively good loss.

Review cue. Recheck target modules and chat template when changing the base-model family or Transformers/PEFT version.

8. Understand GRPO before running a trainer

Outcome. Compute group-relative advantages, clipping, KL pressure, and identify reward and generation bottlenecks.
Recall first. What happens to normalized group advantages when every completion in a prompt group receives the same reward?

Group Relative Policy Optimization samples several completions for each prompt, scores them, and normalizes rewards within the group. Completions with above-average group rewards receive positive relative advantages, while those with below-average rewards receive negative advantages. A clipped policy-ratio objective limits large updates, while a reference-policy KL term can resist drift.

Zero-variance reward groups carry no relative ranking signal and need defined handling. Group size, temperature, completion length, reward scale, clipping, KL coefficient, and reward normalization all change learning. Reward hacking occurs when the model exploits the scoring function without satisfying the intended task.

Generation can dominate online post-training time. A trainer may use vLLM generation in a colocated or server arrangement, trading transfer and memory boundaries. The course first isolates objective math, then runs only a short educational trainer with a deterministic reward. It does not claim alignment or convergence.

A production post-training loop is also a GPU scheduling system: an orchestrator sends prompts to a rollout engine, a reward/verifier or isolated sandbox scores completions, a training backend updates the policy, and new weights or checkpoints move back to rollout workers. A reference policy may be needed for KL control. Collocation reduces weight-transfer distance but makes rollout and training contend for memory; disaggregation isolates phases but adds transfer and idle-time risks; asynchronous rollouts raise utilization while introducing policy staleness. Measure useful accepted tokens, rollout-length stragglers, reward validity, weight age, and end-to-end update cadence.

Worked example

Rewards [1, 2, 5] have a mean below 5, so the third completion gets positive relative advantage while the first gets negative. Rewards [3, 3, 3] yield zero centered advantage; dividing by near-zero variation requires stabilization and provides no ranking signal.

Practice

Run Lab 06 and manually recompute one group. Then run Lab 07 and separate generation time, reward computation, training update, and memory. Write one reward-hacking example for a length reward.

Check your reasoning

The objective lab should satisfy centered-advantage and finite-gradient invariants. A length reward can be hacked by verbose output unrelated to task correctness. The short trainer proves API/mechanics only; useful post-training needs validated rewards, held-out evaluation, safety review, and much more evidence.

Review cue. Revisit the objective whenever trainer or vLLM integration changes; version-sensitive defaults can alter behavior.

A deployable model is a versioned bundle, not one weight file. config.json declares architecture fields such as hidden size, layers, attention heads, KV heads, context limit, and positional strategy. 10. Follow one prompt through autoregressive inference

Outcome. Trace a request from prompt formatting and tokenization through prefill, next-token selection, repeated decode, stopping, and detokenization.
Recall first. Which training-only states disappear during inference, and which new state grows as tokens are generated?

Inference uses learned parameters without computing gradients or optimizer updates. A request first applies the same pinned tokenizer and template expected by the model. The resulting prompt token IDs enter the model. Prefill processes all prompt positions, creates contextual hidden states, produces logits for the next token, and stores attention keys and values for later reuse.

A decoding policy selects one next token ID from the newest logits. That ID is appended to the sequence. Decode then processes the new position using the existing KV cache, produces new logits, and appends the new position’s keys and values. The select–append–decode loop repeats until an end token, stop sequence, maximum length, or another declared stopping rule ends generation.

Detokenization converts generated IDs back into text pieces and then visible text. Streaming can expose partial text before generation finishes, but an HTTP chunk is not guaranteed to represent exactly one model token. Client-observed time also includes queueing, network and serialization, tokenization, scheduling, prefill, decode gaps, and finalization.

This lifecycle creates two distinct correctness contracts. Model semantics require the same prompt IDs, generation policy, cache behavior, and stopping rules. Service semantics require complete, ordered output and correct error/finish behavior. Performance optimization must preserve both.

Worked example

A 1,000-token prompt is tokenized and processed in one prefill phase. The server then selects token 1, decodes one new position, appends its K/V entries, selects token 2, and repeats. Generating 100 tokens therefore requires 100 sequential decode iterations, even though each iteration parallelizes work across layers, heads, and active requests.

Practice

Check your reasoning

The parameters remain fixed. Prompt K/V entries are created during prefill; each decode iteration reads prior entries and appends one position per active sequence. The output ends only when the configured stopping rule fires.

11. Separate prefill, decode, and the KV cache

Outcome. Explain phase-specific work, cache contents, memory growth, and why decode is difficult to saturate.
Recall first. Does the KV cache store model weights, attention keys/values, or generated text strings?

Prefill processes all prompt tokens, computes causal attention for the prompt, and writes keys and values for every layer. It presents large matrix-rich work and often uses the GPU efficiently. Decode processes one new token per active sequence, reads prior cached keys/values, appends new entries, and repeats sequentially.

The KV cache stores projected attention keys and values, not model weights or text strings. A rough byte model multiplies layers × active sequences × cached tokens × key/value heads × head dimension × two tensors × bytes per element. Model-specific layouts, blocks, alignment, and hybrid attention change actual allocation.

Without a cache, each decode step recomputes the prefix and work grows rapidly with generated length. With a cache, projection reuse is high but every step reads a growing history. Decode is often sensitive to memory traffic, batch membership, launch overhead, and scheduler decisions. Grouped-query attention reduces key/value head count and therefore cache bytes.

Worked example

For 32 layers, 8 KV heads, head dimension 128, BF16, batch 16, and 2,048 cached tokens, the rough cache is 32×16×2048×8×128×2×2 bytes, about 4 GiB before allocator/block overhead. Doubling active sequences or cached tokens doubles that estimate.

Practice

Run Labs 08 and 09. Verify cached and recomputed outputs agree, then compare prefill and per-token decode separately. Calculate rough cache bytes from the model configuration and compare with the measured or engine-reported value.

Check your reasoning

Output agreement proves semantic reuse for the tested path. Prefill and decode numbers are not combined because their shapes and objectives differ. Differences between rough and measured cache can come from KV heads, dtype, blocks, alignment, allocator reservation, or extra engine state.

Review cue. Review this ledger for every change in context length, concurrency, KV dtype, attention type, or parallelism.

12. Keep decoding semantics fixed while measuring inference

Outcome. Explain greedy, temperature, top-k/top-p, stopping, and quality gates as part of the workload.
Recall first. Why can two serving benchmarks with identical prompts but different max_tokens or temperature not be compared as the same workload?

Logits become a token through a decoding policy. Greedy decoding selects the highest logit. Temperature rescales logits before softmax; top-k limits candidates by count; top-p limits them by cumulative probability. Repetition controls, stop tokens, minimum/maximum length, and random seed affect output length and kernel work.

Performance depends strongly on prompt and output lengths. Early EOS shortens decode, while a fixed maximum can keep sequences active. Sampling can add small GPU/CPU operations and change continuous-batch membership. Deterministic temperature-zero tests are useful for correctness and repeatability, but they may not represent a stochastic production workload.

Quality is inseparable from inference optimization. Compare generated outputs or task scores with the same template and policy. Quantization, precision, speculative decoding, and model changes can alter distribution even when the server API remains compatible.

Worked example

Server A generates 32 tokens greedily; Server B samples up to 256 tokens and stops on EOS. B's greater latency may come from longer outputs rather than a slower engine. Normalize or report prompt tokens, generated tokens, policy, and finish reasons before attributing the difference.

Practice

Run Lab 17, then define two benchmark profiles: deterministic regression and representative stochastic load. List fixed template, prompt distribution, output-length rule, seed policy, and quality check for each.

Check your reasoning

The regression profile prioritizes repeatability—often temperature zero and bounded tokens. The load profile matches real policy and length distributions and reports them. Neither result is valid without finish reasons and token accounting.

Review cue. Whenever inference performance changes, first verify that generated-token counts and stopping semantics did not change.

Part III · Training performance optimization

13. Build a phase-aware training memory ledger

Outcome. Attribute training peak bytes to parameters, gradients, optimizer state, activations, temporaries, and communication buffers.
Recall first. Why is multiplying model parameter count by two bytes not enough to predict BF16 training memory?

Training holds model parameters, gradient buffers, optimizer state, saved activations, temporary operator workspaces, allocator reservation, and distributed communication buffers. Mixed precision may store or compute different entries in different formats. A checkpoint file is not this live memory footprint: runtime state includes tensors and workspaces that never appear as model weights on disk.

Memory changes over the step. Forward grows saved activations. Backward consumes or recomputes activations while creating gradients. The optimizer reads gradients and moment state and may create temporary buffers. Distributed execution can add gradient buckets, parameter-gather buffers, or shards. Reset PyTorch peak statistics at a declared boundary and record phase-specific peaks rather than one post-step snapshot.

18. Build the inference and KV-cache memory ledger

Outcome. Separate fixed model memory, prefill temporaries, decode state, KV-cache capacity, engine reservation, and allocator overhead.
Recall first. Which inference memory entry grows with active cached tokens even though model weights remain unchanged?

Inference removes training gradients and optimizer state, but it is not just “weights in HBM.” Fixed state includes model weights and engine metadata. Loading and warm-up can create staging buffers or compiled artifacts. Prefill uses temporary activations and workspaces for many prompt positions. Decode retains the KV cache for every active sequence and needs smaller per-step activations. The peak can occur during loading, prefill, a long mixed batch, or decode under high concurrency.

A rough KV-cache model is layers × active sequences × cached tokens × KV heads × head dimension × 2 × bytes per element. The factor of two represents keys and values. Real allocation adds blocks, alignment, metadata, reserved capacity, fragmentation, and model-specific attention layouts. Grouped-query or multi-query attention reduces KV-head count; lower KV dtype reduces bytes only when the engine and model path support it and quality remains acceptable.

Serving engines often reserve a configured fraction of available memory for KV blocks. Reserved memory is capacity for future requests, not automatically a leak. When the block pool becomes scarce, requests may queue, preempt, recompute, swap, or fail according to engine behavior. Measure total and free blocks, cache usage, preemption, request lengths, and concurrency together.

Tensor parallelism can shard model weights, but it may replicate or partition other state differently and adds communication. Quantization reduces selected weight or cache storage only for supported kernels and artifacts. Prefix caching can share immutable prefix blocks across requests; continuous batching changes which sequences own blocks. Each technique changes a specific ledger entry and may shift the latency bottleneck.

The first is not necessarily leaking—it may admit more cached tokens. Compare cache capacity, preemption, request success, and latency under the same length distribution.

19. Measure TTFT, inter-token latency, throughput, queueing, and tails

Outcome. Build a load test that separates client, queue, prefill, decode, and completion behavior.
Recall first. Which metric covers arrival to first generated content, and which covers spacing during streamed decode?

TTFT covers arrival through queueing and prefill to the first output. Inter-token latency (ITL) is the distribution of gaps between successive generated tokens at a declared observation boundary. Time per output token (TPOT) is an aggregate decode measure, commonly decode duration divided by the number of output-token intervals. Do not treat the aggregate as the gap distribution. End-to-end latency covers the complete request. Prompt and generation throughput count different tokens. Tail percentiles expose long prompts, queueing, preemption, and scheduler interference hidden by medians.

Start with a loopback client so network variability is bounded, but separate client saturation from server saturation. Complete model loading, compilation, and CUDA Graph capture before measurement unless startup is the objective. Sweep concurrency under a fixed prompt/output distribution and collect server metrics alongside client measurements.

An open-loop test sends arrivals according to a rate process even when earlier requests are outstanding; it exposes queue growth and overload. A closed-loop test keeps a fixed number of clients or outstanding requests and sends the next request after completion; it measures concurrency behavior but applies backpressure. Never compare results without naming the arrival model. Goodput counts only completed requests or tokens that also meet all declared latency, error, and quality limits.

20. Optimize continuous batching, KV allocation, and prefill scheduling

Outcome. Explain how a serving scheduler trades throughput, latency, and KV-cache pressure as requests arrive and finish.
Recall first. How does continuous batching differ from waiting to form one fixed batch and running it to completion?

Continuous batching changes the active set at scheduling steps: new requests can enter as others finish, so short outputs do not hold a fixed batch open. This raises GPU occupancy and throughput but adds scheduling and queueing tradeoffs. Capacity is a curve over concurrency and length distributions.

Paged KV management allocates cache in blocks to reduce contiguous-allocation pressure and support changing sequence lengths. Prefix caching can reuse KV blocks for identical token prefixes under engine-defined cache identity. It saves prefill work only on actual hits and must respect model, adapter, template, and isolation boundaries. Report queries and hits, not an assumed hit rate.

Chunked prefill splits long prompts so prefill can share scheduling capacity with decode. Larger token budgets can raise throughput but harm decode latency; smaller budgets can protect inter-token latency while delaying long prompts. The attention backend must fit the phase: prefill benefits from Flash/SDPA-style kernels over many prompt positions, while decode backends must efficiently read paged KV state for one new position per active sequence. Backend selection also depends on dtype, head dimension, mask, sequence length, page layout, and engine version. Verify the selected backend and profile both phases instead of assuming one attention kernel owns the entire request.

CUDA Graph replay can reduce repeated CPU launch overhead when the operation graph, tensor shapes, memory addresses, and control flow are stable. Serving engines often warm and capture several batch/token buckets, then route matching scheduler steps to a captured graph and use eager or compiled fallback for unmatched shapes. Capture adds startup time and private memory pools; too many buckets consume memory, while too few increase padding or fallback. Verify graph use on a timeline and report capture policy, warm-up, bucket, fallback rate, and memory change.

Speculative decoding proposes several tokens with a cheaper source, then verifies them with the target model in parallel. Proposal families include a separate draft model, prompt/ngram lookup, multi-token prediction heads, and other engine-supported proposers. In the standard autoregressive flow, the verifier evaluates the proposed positions and the position after the final proposal. It commits the longest accepted draft prefix; at the first mismatch it emits or samples a target-consistent recovery token, while full acceptance can also commit the target's next “bonus” token from that verification call. The exact sampling correction is algorithm- and engine-specific. Benefit depends on accepted tokens and bonus tokens per verification step, proposal cost, target verification shape, output distribution, concurrency, and extra model/KV memory. Preserve the target sampling/quality contract and report proposed drafts, accepted-prefix histogram, recovery/bonus tokens, target verification calls, latency, throughput, and memory.

Multi-LoRA serving keeps a base model resident while selecting compatible adapters per request. It introduces adapter memory, loading and eviction, lineage, authorization, and batching considerations; measure the real adapter/request distribution rather than assuming free multiplexing. Multimodal serving adds modality-specific preprocessing and encoders, placeholder tokens, input limits, caches, and quality checks. Benchmark preprocessing, encoder/prefill work, input dimensions, and model output together. Both remain advanced extensions because they require additional artifacts and modality-specific acceptance data.

The decode steps match a captured bucket, but the long prefill falls back because its token count is outside captured shapes. Separately, a four-token proposer averages only 0.4 accepted draft tokens per verification step, so its extra work is unlikely to repay itself. from __future__ import annotations

import argparse
import math
import statistics

from common import (
    add_common_args,
    load_torch,
    open_private_exclusive,
    require_h100,
    seed_everything,
    validate_common_args,
    write_result,
)
from tiny_lm import build_tiny_lm, make_language_batch


def main() -> None:
    parser = argparse.ArgumentParser(description=__doc__)
    add_common_args(parser)
    parser.add_argument("--save-checkpoint", action="store_true")
    args = parser.parse_args()
    validate_common_args(args)
    torch = load_torch()
    environment = require_h100(torch)
    seed_everything(torch, args.seed)

    hidden, layers, heads, sequence, batch = (
        (512, 4, 8, 256, 8) if args.profile == "smoke" else (2_048, 12, 16, 1_024, 4)
    )
    vocab_size = 4_096
    model = build_tiny_lm(
        torch,
        vocab_size=vocab_size,
        hidden_size=hidden,
        layers=layers,
        heads=heads,
        max_sequence=sequence,
    ).to("cuda")
    optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)
    inputs, labels = make_language_batch(
        torch,
        batch_size=batch,
        sequence=sequence,
        vocab_size=vocab_size,
        device="cuda",
    )
    samples: list[float] = []
    losses: list[float] = []
    gradient_norms: list[float] = []
    trainable_parameters = [
        parameter for parameter in model.parameters() if parameter.requires_grad
    ]

    def train_step() -> tuple[object, object]:
        with torch.autocast(device_type="cuda", dtype=torch.bfloat16):
            logits = model(inputs)
            loss = torch.nn.functional.cross_entropy(
                logits.reshape(-1, vocab_size), labels.reshape(-1)
            )
        loss.backward()
        if any(parameter.grad is None for parameter in trainable_parameters):
            raise SystemExit("At least one trainable parameter has no gradient.")
        gradient_norm = torch.nn.utils.clip_grad_norm_(
            trainable_parameters,
            1.0,
            error_if_nonfinite=True,
        )
        optimizer.step()
        optimizer.zero_grad(set_to_none=True)
        return loss.detach(), gradient_norm.detach()

    for _ in range(args.warmup):
        train_step()
    torch.cuda.synchronize()
    tracked_parameter = trainable_parameters[0]
    parameter_before = tracked_parameter.detach().float().cpu().clone()
    torch.cuda.synchronize()
    baseline_allocated_bytes = int(torch.cuda.memory_allocated())
    baseline_reserved_bytes = int(torch.cuda.memory_reserved())
    torch.cuda.reset_peak_memory_stats()
    for _ in range(args.iterations):
        start = torch.cuda.Event(enable_timing=True)
        end = torch.cuda.Event(enable_timing=True)
        start.record()
        loss, gradient_norm = train_step()
        end.record()
        end.synchronize()
        samples.append(float(start.elapsed_time(end)))
        losses.append(float(loss))
        gradient_norms.append(float(gradient_norm))

    peak_allocated_bytes = int(torch.cuda.max_memory_allocated())
    peak_reserved_bytes = int(torch.cuda.max_memory_reserved())
    parameter_after = tracked_parameter.detach().float().cpu()
    parameter_delta_l2 = float((parameter_after - parameter_before).norm().item())
    finite_losses = all(math.isfinite(loss) for loss in losses)
    finite_gradients = all(
        math.isfinite(gradient_norm) and gradient_norm > 0
        for gradient_norm in gradient_norms
    )
    parameter_updated = math.isfinite(parameter_delta_l2) and parameter_delta_l2 > 0
    if not finite_losses:
        raise SystemExit("Training produced a non-finite loss.")
    if not finite_gradients:
        raise SystemExit("Training produced a missing, zero, or non-finite gradient.")
    if not parameter_updated:
        raise SystemExit("The optimizer did not update the tracked parameter.")
    tokens = batch * sequence * args.iterations
    if args.save_checkpoint:
        checkpoint = (
            args.output_dir / f"tiny-transformer-checkpoint-run-{args.run_id}.pt"
        )
        with open_private_exclusive(checkpoint, binary=True) as stream:
            torch.save(
                {
                    "model": model.state_dict(),
                    "optimizer": optimizer.state_dict(),
                    "run_id": args.run_id,
                    "step": args.warmup + args.iterations,
                },
                stream,
            )
    target = write_result(
        args,
        lab_id="01_tiny_transformer_train",
        environment=environment,
        measurements={
            "parameters": sum(parameter.numel() for parameter in model.parameters()),
            "tokens": tokens,
            "initial_loss": round(losses[0], 5),
            "final_loss": round(losses[-1], 5),
            "median_step_ms": round(statistics.median(samples), 4),
            "tokens_per_second": round(tokens / (sum(samples) / 1_000), 1),
            "gradient_norm": {
                "initial": round(gradient_norms[0], 6),
                "final": round(gradient_norms[-1], 6),
                "median": round(statistics.median(gradient_norms), 6),
            },
            "memory": {
                "baseline_allocated_bytes": baseline_allocated_bytes,
                "baseline_reserved_bytes": baseline_reserved_bytes,
                "peak_allocated_bytes": peak_allocated_bytes,
                "peak_reserved_bytes": peak_reserved_bytes,
                "incremental_peak_allocated_bytes": (
                    peak_allocated_bytes - baseline_allocated_bytes
                ),
                "incremental_peak_reserved_bytes": (
                    peak_reserved_bytes - baseline_reserved_bytes
                ),
            },
            "parameter_delta_l2": round(parameter_delta_l2, 8),
        },
        correctness={
            "finite_loss": True,
            "finite_gradients": True,
            "all_trainable_parameters_had_gradients": True,
            "parameter_updated": True,
        },
    )
    print(f"Completed tiny-transformer training: {target}")


if __name__ == "__main__":
    main()

"""Compare full-batch and microbatch gradient accumulation memory use."""

from __future__ import annotations

import argparse
import statistics
import time

from common import (
    add_common_args,
    load_torch,
    require_h100,
    seed_everything,
    validate_common_args,
    write_result,
)


def main() -> None:
    parser = argparse.ArgumentParser(description=__doc__)
    add_common_args(parser)
    args = parser.parse_args()
    validate_common_args(args)
    torch = load_torch()
    environment = require_h100(torch)
    seed_everything(torch, args.seed)

    width = 2_048 if args.profile == "smoke" else 8_192
    total_batch, microbatch = (64, 16) if args.profile == "smoke" else (128, 16)
    reference = torch.nn.Sequential(
        torch.nn.Linear(width, 4 * width, bias=False),
        torch.nn.GELU(),
        torch.nn.Linear(4 * width, width, bias=False),
    ).to("cuda")
    inputs = torch.randn((total_batch, width), device="cuda")
    targets = torch.randn((total_batch, width), device="cuda")

    def one_pass(model: object, split: int) -> None:
        model.zero_grad(set_to_none=True)
        for start in range(0, total_batch, split):
            with torch.autocast(device_type="cuda", dtype=torch.bfloat16):
                prediction = model(inputs[start : start + split])
                loss = torch.nn.functional.mse_loss(
                    prediction, targets[start : start + split]
                )
                loss = loss * (split / total_batch)
            loss.backward()

    def run(model: object, split: int) -> dict[str, float]:
        for _ in range(args.warmup):
            one_pass(model, split)
        torch.cuda.synchronize()
        elapsed_samples: list[float] = []
        peak_samples: list[float] = []
        for _ in range(args.iterations):
            torch.cuda.reset_peak_memory_stats()
            started = time.perf_counter()
            one_pass(model, split)
            torch.cuda.synchronize()
            elapsed_samples.append((time.perf_counter() - started) * 1_000)
            peak_samples.append(torch.cuda.max_memory_allocated() / 2**20)
        return {
            "median_elapsed_ms": round(statistics.median(elapsed_samples), 4),
            "median_peak_allocated_mib": round(statistics.median(peak_samples), 2),
        }

    full_metrics = run(reference, total_batch)
    full_gradients = [
        parameter.grad.detach().flatten()[:4_096].cpu().clone()
        for parameter in reference.parameters()
    ]
    reference.zero_grad(set_to_none=True)
    torch.cuda.empty_cache()
    micro_metrics = run(reference, microbatch)
    sampled_gradient_error = max(
        float((expected - parameter.grad.detach().flatten()[:4_096].cpu()).abs().max())
        for expected, parameter in zip(full_gradients, reference.parameters())
    )
    if sampled_gradient_error > 2e-3:
        raise SystemExit(
            "Accumulated gradient samples diverged: "
            f"max error {sampled_gradient_error:.6f}"
        )
    target = write_result(
        args,
        lab_id="02_gradient_accumulation",
        environment=environment,
        measurements={
            "total_batch": total_batch,
            "microbatch": microbatch,
            "full_batch": full_metrics,
            "accumulated": micro_metrics,
            "sampled_max_gradient_error": round(sampled_gradient_error, 7),
        },
        correctness={"sampled_gradients_match": True},
    )
    print(f"Completed gradient-accumulation experiment: {target}")


if __name__ == "__main__":
    main()

def main() -> None:
    parser = argparse.ArgumentParser(description=__doc__)
    add_common_args(parser, include_measurement=False)
    parser.add_argument("--group-size", type=int, default=8)
    args = parser.parse_args()
    validate_common_args(args)
    if args.group_size < 2:
        raise SystemExit(
            "--group-size must be at least 2 for within-group normalization"
        )
    torch = load_torch()
    environment = require_h100(torch)
    seed_everything(torch, args.seed)

    prompts = 4
    old_log_probs = torch.randn((prompts, args.group_size), device="cuda") * 0.1
    new_log_probs = (
        old_log_probs + torch.randn_like(old_log_probs) * 0.02
    ).requires_grad_()
    rewards = torch.randn((prompts, args.group_size), device="cuda")
    advantages = (rewards - rewards.mean(dim=1, keepdim=True)) / (
        rewards.std(dim=1, keepdim=True, unbiased=False) + 1e-4
    )
    ratio = (new_log_probs - old_log_probs).exp()
    clipped_ratio = ratio.clamp(0.8, 1.2)
    surrogate = torch.minimum(ratio * advantages, clipped_ratio * advantages)
    reference_log_probs = old_log_probs - 0.01
    log_ratio = reference_log_probs - new_log_probs
    approximate_kl = log_ratio.exp() - log_ratio - 1
    loss = -(surrogate - 0.02 * approximate_kl).mean()
    loss.backward()
    group_mean_error = float(advantages.mean(dim=1).abs().max())
    if group_mean_error > 1e-5 or not torch.isfinite(loss):
        raise SystemExit(
            "The normalized advantages or policy objective failed validation."
        )
    target = write_result(
        args,
        lab_id="06_grpo_objective",
        environment=environment,
        measurements={
            "prompts": prompts,
            "group_size": args.group_size,
            "loss": round(float(loss.detach()), 6),
            "mean_approximate_kl": round(float(approximate_kl.mean()), 7),
            "max_group_advantage_mean_error": round(group_mean_error, 8),
        },
        correctness={
            "zero_mean_advantages": True,
            "finite_gradients": bool(torch.isfinite(new_log_probs.grad).all()),
        },
    )
    print(f"Completed GRPO-objective unpacking: {target}")

from common import (

def main() -> None:
    parser = argparse.ArgumentParser(description=__doc__)
    add_common_args(parser)
    parser.set_defaults(warmup=1, iterations=3)
    args = parser.parse_args()
    validate_common_args(args)
    torch = load_torch()
    environment = require_h100(torch)
    seed_everything(torch, args.seed)

    batch, heads, head_dim = 1, 16, 64
    prompt, generated = (256, 64) if args.profile == "smoke" else (2_048, 256)
    hidden = heads * head_dim
    qkv = torch.nn.Linear(
        hidden, 3 * hidden, bias=False, device="cuda", dtype=torch.bfloat16
    )
    values = torch.randn(
        (batch, prompt + generated, hidden), device="cuda", dtype=torch.bfloat16
    )

    def project(tokens: object) -> tuple[object, object, object]:
        projected = qkv(tokens).view(batch, tokens.shape[1], 3, heads, head_dim)
        query, key, value = projected.unbind(dim=2)
        return query.transpose(1, 2), key.transpose(1, 2), value.transpose(1, 2)

    def full(prefix_length: int) -> object:
        query, key, value = project(values[:, :prefix_length])
        return torch.nn.functional.scaled_dot_product_attention(
            query, key, value, is_causal=True
        )[:, :, -1]

    def build_prompt_cache() -> tuple[object, object, object]:
        query, key, value = project(values[:, :prompt])
        output = torch.nn.functional.scaled_dot_product_attention(
            query, key, value, is_causal=True
        )[:, :, -1]
        return output, key, value

    full_prompt = full(prompt)
    cached_prompt, key_cache, value_cache = build_prompt_cache()
    max_error = float((full_prompt - cached_prompt).abs().max())
    if max_error > 2e-2:
        raise SystemExit(f"Cached and full prompt outputs diverged: {max_error:.6f}")

    def recompute_decode() -> object:
        output = None
        for step in range(generated):
            output = full(prompt + step + 1)
        return output

    def cached_decode() -> object:
        key = key_cache
        value = value_cache
        output = None
        for step in range(generated):
            query, next_key, next_value = project(
                values[:, prompt + step : prompt + step + 1]
            )
            key = torch.cat((key, next_key), dim=2)
            value = torch.cat((value, next_value), dim=2)
            output = torch.nn.functional.scaled_dot_product_attention(
                query, key, value, is_causal=False
            )
        return output

    recomputed_final = recompute_decode()
    cached_final = cached_decode().squeeze(2)
    decode_error = float((recomputed_final - cached_final).abs().max())
    if decode_error > 2e-2:
        raise SystemExit(
            f"Cached and recomputed decode outputs diverged: {decode_error:.6f}"
        )
    recompute = summarize_ms(
        cuda_times_ms(
            torch,
            recompute_decode,
            warmup=args.warmup,
            iterations=args.iterations,
        )
    )
    cached = summarize_ms(
        cuda_times_ms(
            torch,
            cached_decode,
            warmup=args.warmup,
            iterations=args.iterations,
        )
    )

    target = write_result(

        },
    )

def generation_schedule(*, prompt_tokens: int, new_tokens: int) -> list[GenerationStep]:
    if prompt_tokens < 1:
        raise ValueError("prompt_tokens must be positive")
    if new_tokens < 1:
        raise ValueError("new_tokens must be positive")

            phase="prefill",

        GenerationStep(
            phase="decode",
            input_tokens=1,
            attention_tokens=prompt_tokens + generated_index,
            cache_start=prompt_tokens + generated_index - 1,

        for generated_index in range(1, new_tokens)
    )

def aggregate_outputs(outputs: list[object], *, max_tokens: int) -> dict[str, object]:
    prompt_token_counts = []
    output_token_counts = []
    finish_reasons = []
    for output in outputs:
        prompt_token_ids = output.prompt_token_ids
        if prompt_token_ids is None or not prompt_token_ids:
            raise ValueError("Every request must expose a positive prompt token count.")
        if len(output.outputs) != 1:
            raise ValueError("Every request must contain exactly one completion.")
        completion = output.outputs[0]
        output_tokens = len(completion.token_ids)
        if output_tokens < 1 or output_tokens > max_tokens:
            raise ValueError(
                "Every request must contain a positive bounded output token count."
            )
        prompt_token_counts.append(len(prompt_token_ids))
        output_token_counts.append(output_tokens)
        finish_reasons.append(completion.finish_reason)
    return {
        "request_count": len(outputs),
        "prompt_tokens_total": sum(prompt_token_counts),
        "output_tokens_total": sum(output_token_counts),
        "prompt_tokens_per_request": prompt_token_counts,
        "output_tokens_per_request": output_token_counts,
        "finish_reasons": finish_reasons,
    }

    return {
        "min": min(values),
        "median": statistics.median(values),
        "max": max(values),

def checkpointed_forward(torch: object, model: object, token_ids: object) -> object:
    from torch.utils.checkpoint import checkpoint

    positions = torch.arange(token_ids.shape[1], device=token_ids.device)
    hidden = model.token_embedding(token_ids) + model.position_embedding(positions)
    for block in model.blocks:
        hidden = checkpoint(block, hidden, use_reentrant=False)
    return model.lm_head(model.final_norm(hidden))


def train_samples(
    torch: object,
    model: object,
    inputs: object,
    targets: object,
    *,
    checkpointed: bool,
    warmup: int,
    iterations: int,
) -> tuple[list[float], list[int], list[object]]:
    def step() -> None:
        logits = (
            checkpointed_forward(torch, model, inputs)
            if checkpointed
            else model(inputs)
        )
        loss = torch.nn.functional.cross_entropy(
            logits.reshape(-1, logits.shape[-1]), targets.reshape(-1)
        )
        loss.backward()

    for _ in range(warmup):
        model.zero_grad(set_to_none=True)
        step()
    torch.cuda.synchronize()

    timings = []
    incremental_peaks = []
    gradients = []
    for _ in range(iterations):
        model.zero_grad(set_to_none=True)
        torch.cuda.empty_cache()
        baseline_bytes = int(torch.cuda.memory_allocated())
        torch.cuda.reset_peak_memory_stats()
        start = torch.cuda.Event(enable_timing=True)
        end = torch.cuda.Event(enable_timing=True)
        start.record()
        step()
        end.record()
        end.synchronize()
        timings.append(float(start.elapsed_time(end)))
        incremental_peaks.append(
            int(torch.cuda.max_memory_allocated()) - baseline_bytes
        )
        gradients = [
            parameter.grad.detach().float().cpu().clone()
            for parameter in model.parameters()
            if parameter.grad is not None
        ]
    return timings, incremental_peaks, gradients

def main() -> None:
    parser = argparse.ArgumentParser(description=__doc__)
    add_common_args(parser)
    args = parser.parse_args()
    validate_common_args(args)
    torch = load_torch()
    environment = require_h100(torch)
    seed_everything(torch, args.seed)
    rank, world_size, local_rank = init_nccl(torch)
    device = f"cuda:{local_rank}"
    width = 2_048 if args.profile == "smoke" else 8_192
    batch = 32 if args.profile == "smoke" else 128
    if width % world_size:
        raise SystemExit("The hidden width must be divisible by the rank count.")
    inputs = torch.randn((batch, width), device=device, dtype=torch.bfloat16)
    weight = torch.randn((width, width), device=device, dtype=torch.bfloat16)
    reference = inputs @ weight.T
    column_weight = weight.chunk(world_size, dim=0)[rank].contiguous()
    row_weight = weight.chunk(world_size, dim=1)[rank].contiguous()
    row_input = inputs.chunk(world_size, dim=1)[rank].contiguous()

    def column_parallel() -> object:
        local_output = inputs @ column_weight.T
        gathered = [torch.empty_like(local_output) for _ in range(world_size)]
        torch.distributed.all_gather(gathered, local_output)
        return torch.cat(gathered, dim=-1)

    def row_parallel() -> object:
        output = row_input @ row_weight.T
        torch.distributed.all_reduce(output)
        return output

    def measure(operation: Callable[[], object]) -> list[float]:
        for _ in range(args.warmup):
            operation()
        torch.cuda.synchronize()
        samples: list[float] = []
        for _ in range(args.iterations):
            torch.distributed.barrier()
            started = time.perf_counter()
            operation()
            torch.cuda.synchronize()
            elapsed = torch.tensor(
                (time.perf_counter() - started) * 1_000,
                device=device,
                dtype=torch.float64,
            )
            torch.distributed.all_reduce(elapsed, op=torch.distributed.ReduceOp.MAX)
            samples.append(float(elapsed.item()))
        return samples

    column_samples = measure(column_parallel)
    row_samples = measure(row_parallel)
    column_output = column_parallel()
    row_output = row_parallel()
    column_error = torch.linalg.vector_norm(
        column_output.float() - reference.float()
    ) / torch.linalg.vector_norm(reference.float()).clamp_min(1e-12)
    row_error = torch.linalg.vector_norm(
        row_output.float() - reference.float()
    ) / torch.linalg.vector_norm(reference.float()).clamp_min(1e-12)
    max_error = max(float(column_error.item()), float(row_error.item()))
    local_ok = torch.tensor(int(max_error < 0.02), device=device, dtype=torch.int32)
    torch.distributed.all_reduce(local_ok, op=torch.distributed.ReduceOp.MIN)
    if not bool(local_ok.item()):
        raise SystemExit(f"Tensor-parallel outputs diverged: relative L2={max_error}")

        target = write_result(

            environment={**environment, "rank_count": world_size},

def relative_error(candidate: float, reference: float) -> float:
    """Return scalar relative error with a stable near-zero denominator."""
    return abs(candidate - reference) / max(abs(reference), 1e-12)


def state_relative_l2(
    candidate: dict[str, Any],
    reference: dict[str, Any],
) -> float:
    """Compute relative L2 over matching named tensors without concatenation."""
    if candidate.keys() != reference.keys():
        raise SystemExit("Numerical comparison encountered different parameter sets.")
    difference_squared = 0.0
    reference_squared = 0.0
    for name, reference_value in reference.items():
        candidate_value = candidate[name]
        difference_squared += float((candidate_value - reference_value).square().sum())
        reference_squared += float(reference_value.square().sum())
    return math.sqrt(difference_squared) / max(math.sqrt(reference_squared), 1e-12)


def numerical_step(
    torch: Any,
    *,
    autocast_dtype: Any | None,
    initial_state: dict[str, Any],
    inputs: Any,
    labels: Any,
    vocab_size: int,
    model_shape: dict[str, int],
    seed: int,
) -> tuple[dict[str, Any], dict[str, dict[str, Any]]]:
    """Capture one update from identical weights, data, and random state."""
    seed_everything(torch, seed)
    model = build_tiny_lm(
        torch,
        vocab_size=vocab_size,
        hidden_size=model_shape["hidden"],
        layers=model_shape["layers"],
        heads=model_shape["heads"],
        max_sequence=model_shape["sequence"],
    ).to("cuda")
    model.load_state_dict(initial_state)
    model.train()
    optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)
    use_fp16_scaler = autocast_dtype == torch.float16
    scaler = torch.amp.GradScaler("cuda", enabled=use_fp16_scaler)
    optimizer.zero_grad(set_to_none=True)
    with torch.autocast(
        device_type="cuda",
        dtype=autocast_dtype,
        enabled=autocast_dtype is not None,
    ):
        logits = model(inputs)
        loss = torch.nn.functional.cross_entropy(
            logits.reshape(-1, vocab_size), labels.reshape(-1)
        )
    scaler.scale(loss).backward()
    scaler.unscale_(optimizer)

    gradients: dict[str, Any] = {}
    finite = bool(torch.isfinite(loss))
    for name, parameter in model.named_parameters():
        if parameter.grad is None:
            raise SystemExit(f"Missing gradient for {name} in numerical comparison.")
        value = parameter.grad.detach().float().cpu()
        gradients[name] = value
        finite = finite and bool(torch.isfinite(value).all())
    gradient_l2 = math.sqrt(
        sum(float(value.square().sum()) for value in gradients.values())
    )

    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    scaler.step(optimizer)
    scaler.update()
    updates: dict[str, Any] = {}
    for name, parameter in model.named_parameters():
        value = parameter.detach().float().cpu() - initial_state[name].float()
        updates[name] = value
        finite = finite and bool(torch.isfinite(value).all())
    update_l2 = math.sqrt(
        sum(float(value.square().sum()) for value in updates.values())
    )
    if not finite or update_l2 <= 0:
        raise SystemExit(
            "A numerical comparison path was non-finite or did not update."
        )
    record = {
        "pre_update_loss": float(loss.detach()),
        "unclipped_gradient_l2": gradient_l2,
        "parameter_update_l2": update_l2,
        "parameters_remain_fp32": all(
            parameter.dtype == torch.float32 for parameter in model.parameters()
        ),
        "uses_dynamic_gradient_scaling": use_fp16_scaler,
        "gradient_scale_after_step": float(scaler.get_scale()),
        "finite_loss_gradients_and_update": finite,
    }
    return record, {"gradients": gradients, "updates": updates}


def train_mode(
    torch: Any,
    *,
    name: str,
    autocast_dtype: Any | None,
    initial_state: dict[str, Any],
    inputs: Any,
    labels: Any,
    vocab_size: int,
    model_shape: dict[str, int],
    seed: int,
    warmup: int,
    iterations: int,
) -> dict[str, Any]:
    """Measure a warmed multi-step run separately from the equivalence step."""
    seed_everything(torch, seed)
    model = build_tiny_lm(
        torch,
        vocab_size=vocab_size,
        hidden_size=model_shape["hidden"],
        layers=model_shape["layers"],
        heads=model_shape["heads"],
        max_sequence=model_shape["sequence"],
    ).to("cuda")
    model.load_state_dict(initial_state)
    model.train()
    optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)
    use_fp16_scaler = autocast_dtype == torch.float16
    scaler = torch.amp.GradScaler("cuda", enabled=use_fp16_scaler)
    first_parameter = next(model.parameters())
    initial_parameter = first_parameter.detach().clone()

    def one_step() -> tuple[Any, Any]:
        optimizer.zero_grad(set_to_none=True)
        with torch.autocast(
            device_type="cuda",
            dtype=autocast_dtype,
            enabled=autocast_dtype is not None,
        ):
            logits = model(inputs)
            loss = torch.nn.functional.cross_entropy(
                logits.reshape(-1, vocab_size), labels.reshape(-1)
            )
        scaler.scale(loss).backward()
        scaler.unscale_(optimizer)
        gradient_norm = torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        scaler.step(optimizer)
        scaler.update()
        return loss.detach(), gradient_norm.detach()

    for _ in range(warmup):
        one_step()
    torch.cuda.synchronize()
    torch.cuda.reset_peak_memory_stats()
    device_samples: list[float] = []
    end_to_end_samples: list[float] = []
    losses: list[float] = []
    gradient_norms: list[float] = []
    for _ in range(iterations):
        torch.cuda.synchronize()
        wall_started = time.perf_counter()
        start = torch.cuda.Event(enable_timing=True)
        end = torch.cuda.Event(enable_timing=True)
        start.record()
        loss, gradient_norm = one_step()
        end.record()
        end.synchronize()
        end_to_end_samples.append((time.perf_counter() - wall_started) * 1_000)
        device_samples.append(float(start.elapsed_time(end)))
        losses.append(float(loss))
        gradient_norms.append(float(gradient_norm))

    parameter_delta = float(
        (first_parameter.detach() - initial_parameter).float().norm()
    )
    finite = all(
        torch.isfinite(torch.tensor(values)).all().item()
        for values in (losses, gradient_norms)
    )
    if not finite or parameter_delta <= 0:
        raise SystemExit(f"{name} failed the finite-update correctness gate.")
    tokens = int(inputs.numel()) * iterations
    result = {
        "autocast_dtype": str(autocast_dtype).removeprefix("torch."),
        "parameters_remain_fp32": all(
            parameter.dtype == torch.float32 for parameter in model.parameters()
        ),
        "uses_dynamic_gradient_scaling": use_fp16_scaler,
        "final_gradient_scale": float(scaler.get_scale()),
        "median_device_region_ms": round(statistics.median(device_samples), 4),
        "median_end_to_end_step_ms": round(statistics.median(end_to_end_samples), 4),
        "p90_end_to_end_step_ms": round(
            sorted(end_to_end_samples)[
                max(0, math.ceil(0.9 * len(end_to_end_samples)) - 1)
            ],
            4,
        ),
        "end_to_end_tokens_per_second": round(
            tokens / (sum(end_to_end_samples) / 1_000), 1
        ),
        "first_timed_loss_after_warmup": round(losses[0], 6),
        "final_measured_loss": round(losses[-1], 6),
        "final_gradient_norm": round(gradient_norms[-1], 6),
        "parameter_delta_l2": round(parameter_delta, 6),
        "peak_allocated_mib": round(torch.cuda.max_memory_allocated() / 2**20, 1),
        "peak_reserved_mib": round(torch.cuda.max_memory_reserved() / 2**20, 1),
    }

def relative_l2(torch: Any, candidate: Any, reference: Any) -> float:
    numerator = (candidate.float() - reference.float()).norm()
    denominator = reference.float().norm().clamp_min(1e-12)
    return float(numerator / denominator)


def measure_steps(
    torch: Any,
    operation: Callable[[], tuple[Any, Any]],
    *,
    warmup: int,
    iterations: int,
) -> tuple[list[float], dict[str, float]]:
    for _ in range(warmup):
        operation()
    torch.cuda.synchronize()
    steady_state_bytes = torch.cuda.memory_allocated()
    torch.cuda.reset_peak_memory_stats()
    samples: list[float] = []
    for _ in range(iterations):
        start = torch.cuda.Event(enable_timing=True)
        end = torch.cuda.Event(enable_timing=True)
        start.record()
        operation()
        end.record()
        end.synchronize()
        samples.append(float(start.elapsed_time(end)))
    peak_bytes = torch.cuda.max_memory_allocated()
    memory = {
        "steady_state_allocated_mib": steady_state_bytes / 2**20,
        "incremental_peak_above_baseline_mib": max(0, peak_bytes - steady_state_bytes)
        / 2**20,
    }
    return samples, memory

        bf16_output, bf16_gradient = bf16_step()
        fp8_output, fp8_gradient = fp8_step()

        fp8_step,
        warmup=args.warmup,

from __future__ import annotations

import argparse
import statistics

from collections import Counter
from typing import Any

from common import (

def main() -> None:
    parser = argparse.ArgumentParser(description=__doc__)
    add_common_args(parser)
    parser.add_argument("--draft-length", type=int, default=4)
    parser.add_argument("--max-new-tokens", type=int, default=32)
    args = parser.parse_args()
    validate_common_args(args)
    if (
        args.draft_length < 1
        or args.max_new_tokens < 2
        or args.max_new_tokens <= args.draft_length
    ):
        raise SystemExit(
            "--draft-length must be positive and --max-new-tokens must be greater "
            "than --draft-length so the full-acceptance path has room for a target "
            "bonus token."
        )
    torch = load_torch()
    environment = require_h100(torch)
    seed_everything(torch, args.seed)

    vocab_size, hidden = (2_048, 512) if args.profile == "smoke" else (8_192, 2_048)

    class TargetTransition(torch.nn.Module):
        def __init__(self) -> None:
            super().__init__()
            self.embedding = torch.nn.Embedding(vocab_size, hidden)
            self.projection = torch.nn.Linear(hidden, vocab_size, bias=False)

        def forward(self, token_ids: Any) -> Any:
            return self.projection(torch.nn.functional.gelu(self.embedding(token_ids)))

    target_model = TargetTransition().to("cuda").eval()
    with torch.inference_mode():
        all_tokens = torch.arange(vocab_size, device="cuda")
        ideal_draft = target_model(all_tokens).argmax(dim=-1).cpu().tolist()
    poor_draft = [int((token + 1) % vocab_size) for token in ideal_draft]
    start_token = args.seed % vocab_size

    @torch.inference_mode()
    def target_only() -> tuple[list[int], int]:
        current = start_token
        generated: list[int] = []
        calls = 0
        while len(generated) < args.max_new_tokens:
            token = int(
                target_model(torch.tensor([current], device="cuda"))
                .argmax(dim=-1)
                .item()
            )
            generated.append(token)
            current = token
            calls += 1
        return generated, calls

    @torch.inference_mode()
    def speculative(
        draft_table: list[int],
    ) -> tuple[list[int], int, list[int], int, int, int]:
        current = start_token
        generated: list[int] = []
        target_calls = 0
        accepted_lengths: list[int] = []
        proposal_count = 0
        bonus_count = 0
        recovered_count = 0
        while len(generated) < args.max_new_tokens:
            limit = min(args.draft_length, args.max_new_tokens - len(generated))
            proposals: list[int] = []
            draft_current = current
            for _ in range(limit):
                draft_current = draft_table[draft_current]
                proposals.append(draft_current)
            proposal_count += len(proposals)
            verification_inputs = [current, *proposals]
            verified = (
                target_model(torch.tensor(verification_inputs, device="cuda"))
                .argmax(dim=-1)
                .cpu()
                .tolist()
            )
            target_calls += 1
            accepted = 0
            for proposed, target_token in zip(proposals, verified[:-1], strict=True):
                if proposed == target_token:
                    generated.append(proposed)
                    current = proposed
                    accepted += 1
                else:
                    generated.append(target_token)
                    current = target_token
                    recovered_count += 1
                    break
            else:
                if len(generated) < args.max_new_tokens:
                    bonus_token = verified[-1]
                    generated.append(bonus_token)
                    current = bonus_token
                    bonus_count += 1
            accepted_lengths.append(accepted)
        return (
            generated,
            target_calls,
            accepted_lengths,
            proposal_count,
            bonus_count,
            recovered_count,
        )

    def time_case(operation: Any) -> tuple[list[float], Any, float]:
        for _ in range(args.warmup):
            operation()
        torch.cuda.synchronize()
        torch.cuda.reset_peak_memory_stats()
        samples: list[float] = []
        last_result: Any = None
        for _ in range(args.iterations):
            torch.cuda.synchronize()
            started = time.perf_counter()
            last_result = operation()
            torch.cuda.synchronize()
            samples.append((time.perf_counter() - started) * 1_000)
        peak_mib = torch.cuda.max_memory_allocated() / 2**20
        return samples, last_result, peak_mib

    baseline_samples, baseline_result, baseline_peak = time_case(target_only)
    high_samples, high_result, high_peak = time_case(lambda: speculative(ideal_draft))
    low_samples, low_result, low_peak = time_case(lambda: speculative(poor_draft))
    baseline_tokens, baseline_calls = baseline_result
    (
        high_tokens,
        high_calls,
        high_accepts,
        high_proposals,
        high_bonuses,
        high_recovered,
    ) = high_result
    (
        low_tokens,
        low_calls,
        low_accepts,
        low_proposals,
        low_bonuses,
        low_recovered,
    ) = low_result
    exact = baseline_tokens == high_tokens == low_tokens
    high_reduces_calls = high_calls < baseline_calls
    low_preserves_calls = low_calls == baseline_calls
    high_emits_bonus = high_bonuses > 0
    low_emits_recovery = low_recovered > 0
    if (
        not exact
        or baseline_calls != args.max_new_tokens
        or not high_reduces_calls
        or not low_preserves_calls
        or not high_emits_bonus
        or not low_emits_recovery
    ):
        raise SystemExit(
            "Speculative output or target-call acceptance gates did not pass."
        )

    def case_record(
        samples: list[float],
        calls: int,
        accepted: list[int],
        proposals: int,
        bonus_tokens: int,
        recovered_tokens: int,
    ) -> dict[str, Any]:
        histogram = Counter(accepted)
        return {
            "median_e2e_ms": round(statistics.median(samples), 4),
            "target_forward_calls": calls,
            "draft_tokens_proposed": proposals,
            "accepted_draft_tokens": sum(accepted),
            "target_bonus_tokens": bonus_tokens,
            "target_recovered_tokens": recovered_tokens,
            "mean_accepted_prefix": round(statistics.mean(accepted), 3),
            "accepted_prefix_histogram": {
                str(length): count for length, count in sorted(histogram.items())
            },
        }

    target = write_result(
        args,
        lab_id="23_speculative_decoding",
        environment=environment,
        measurements={
            "mechanism_scope": "greedy first-order synthetic target",
            "vocab_size": vocab_size,
            "hidden_size": hidden,
            "draft_length": args.draft_length,
            "generated_tokens": args.max_new_tokens,
            "target_only": {
                "median_e2e_ms": round(statistics.median(baseline_samples), 4),
                "target_forward_calls": baseline_calls,
                "peak_allocated_mib": round(baseline_peak, 1),
            },
            "high_acceptance": {
                **case_record(
                    high_samples,
                    high_calls,
                    high_accepts,
                    high_proposals,
                    high_bonuses,
                    high_recovered,
                ),
                "peak_allocated_mib": round(high_peak, 1),
            },
            "low_acceptance": {
                **case_record(
                    low_samples,
                    low_calls,
                    low_accepts,
                    low_proposals,
                    low_bonuses,
                    low_recovered,
                ),
                "peak_allocated_mib": round(low_peak, 1),
            },
        },
        correctness={
            "both_speculative_paths_match_target_only_greedy_output": exact,
            "high_acceptance_reduces_target_calls": high_reduces_calls,
            "low_acceptance_does_not_reduce_target_calls": low_preserves_calls,
            "full_acceptance_emits_target_bonus_tokens": high_emits_bonus,
            "first_rejection_emits_target_recovery_tokens": low_emits_recovery,
        },
    )
    print(f"Completed speculative-decoding mechanics comparison: {target}")

"""Small decoder-only transformer used by the distributed training labs."""

from __future__ import annotations

from typing import Any


def build_tiny_lm(
    torch: Any,
    *,
    vocab_size: int,
    hidden_size: int,
    layers: int,
    heads: int,
    max_sequence: int,
) -> Any:
    class CausalSelfAttention(torch.nn.Module):
        def __init__(self) -> None:
            super().__init__()
            self.heads = heads
            self.head_dim = hidden_size // heads
            self.qkv = torch.nn.Linear(hidden_size, 3 * hidden_size, bias=False)
            self.output = torch.nn.Linear(hidden_size, hidden_size, bias=False)

        def forward(self, values: Any) -> Any:
            batch, sequence, _ = values.shape
            qkv = self.qkv(values).view(batch, sequence, 3, self.heads, self.head_dim)
            query, key, value = qkv.unbind(dim=2)
            query = query.transpose(1, 2)
            key = key.transpose(1, 2)
            value = value.transpose(1, 2)
            attended = torch.nn.functional.scaled_dot_product_attention(
                query, key, value, is_causal=True
            )
            attended = (
                attended.transpose(1, 2).contiguous().view(batch, sequence, hidden_size)
            )
            return self.output(attended)

    class Block(torch.nn.Module):
        def __init__(self) -> None:
            super().__init__()
            self.attention_norm = torch.nn.LayerNorm(hidden_size)
            self.attention = CausalSelfAttention()
            self.mlp_norm = torch.nn.LayerNorm(hidden_size)
            self.mlp = torch.nn.Sequential(
                torch.nn.Linear(hidden_size, 4 * hidden_size, bias=False),
                torch.nn.GELU(),
                torch.nn.Linear(4 * hidden_size, hidden_size, bias=False),
            )

        def forward(self, values: Any) -> Any:
            values = values + self.attention(self.attention_norm(values))
            return values + self.mlp(self.mlp_norm(values))

    class TinyCausalLM(torch.nn.Module):
        def __init__(self) -> None:
            super().__init__()
            self.token_embedding = torch.nn.Embedding(vocab_size, hidden_size)
            self.position_embedding = torch.nn.Embedding(max_sequence, hidden_size)
            self.blocks = torch.nn.ModuleList([Block() for _ in range(layers)])
            self.final_norm = torch.nn.LayerNorm(hidden_size)
            self.lm_head = torch.nn.Linear(hidden_size, vocab_size, bias=False)

        def forward(self, token_ids: Any) -> Any:
            positions = torch.arange(token_ids.shape[1], device=token_ids.device)
            hidden = self.token_embedding(token_ids) + self.position_embedding(
                positions
            )
            for block in self.blocks:
                hidden = block(hidden)
            return self.lm_head(self.final_norm(hidden))

    return TinyCausalLM()


def make_language_batch(
    torch: Any,
    *,
    batch_size: int,
    sequence: int,
    vocab_size: int,
    device: str,
    offset: int = 0,
) -> tuple[Any, Any]:
    """Create deterministic next-token data without downloading a dataset."""
    starts = torch.arange(batch_size, device=device).unsqueeze(1) + offset
    steps = torch.arange(sequence + 1, device=device).unsqueeze(0)
    tokens = (starts * 7 + steps * 3 + 11) % vocab_size
    return tokens[:, :-1].long(), tokens[:, 1:].long()
