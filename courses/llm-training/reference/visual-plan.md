# Visual plan

The table defines this course's overview diagrams. The
[visual manifest](visual-manifest.json) links additional detailed diagrams to
their conceptual lessons. Each figure appears within the specified lesson section or after the specified lab section in its declared lesson or lab home,
with accessible labels, captions, and fit-to-width sizing.

The training-lifecycle diagram is inside **How it works** in Lesson 1. It connects
data preparation and tokenization to predictions/loss, gradients, parameter
updates, evaluation and checkpointing before comparing training stages.

| Training decision | Profile an equivalent baseline | Change one causal factor | Check the complete update | Read downward through the acceptance process. Check correctness and complete-step performance under the same learning objective; keep, reject or report uncertainty. A larger utilization ratio alone cannot justify a change. | 16 | How it works | flow | lesson |
| Two ways to save training memory | Small microbatches | Accumulated gradients | Recomputed activations | Compare complementary choices. Small microbatches reduce activation demand. Accumulation retains and combines gradients before one update. Checkpointing retains selected activations and recomputes missing ones during backward. They change different lifetimes and must preserve the declared global objective. | 8 | How it works | comparison | lesson |
| Training execution strategies | Eager: submit operations | Compile: transform regions | Graph: replay dependencies | Compare execution strategies for the same parameter update. Eager execution submits operations individually, compilation may fuse eligible work, and a CUDA Graph replays a prepared dependency plan. Gradients and parameters still change; stable storage does not mean constant values. | 10 | How it works | comparison | lesson |
| Replicated and sharded state | Replicas retain full state | Shards retain owned pieces | Gather needed values | Compare persistent ownership, then the computation boundary. Replication keeps full model state on every rank. Sharding distributes selected persistent state; each computation gathers missing parameter values when required and gradient reduction returns contributions to their owners. Temporary full values still consume memory. | 11 | How it works | comparison | lesson |
