# sfs module

Reusable Terraform module that creates one or more Nebius Shared File Systems
(SFS).

Resources managed:

- `nebius_compute_v1_filesystem`

Out of scope:

- CSI driver installation
- `StorageClass`, `PersistentVolume`, and `PersistentVolumeClaim` lifecycle
- workload-level mounts

Those in-cluster Kubernetes resources are expected to be managed by Flux/GitOps.

## Usage

### Local path source

```hcl
module "sfs" {
  source = "./platform-infra/modules/sfs"

  parent_id      = "project-xxxxxxxx"
  name           = "client-a-prod-sfs"
  size_gib       = 500
  block_size_kib = 4
}
```

### Named filesystems

```hcl
module "sfs" {
  source = "./platform-infra/modules/sfs"

  parent_id = "project-xxxxxxxx"
  filesystems = {
    jail = {
      name      = "client-a-jail"
      size_gib  = 4096
      mount_tag = "jail"
    }
    "controller-spool" = {
      name      = "client-a-controller-spool"
      size_gib  = 100
      mount_tag = "controller-spool"
    }
    accounting = {
      name      = "client-a-accounting"
      size_gib  = 256
      mount_tag = "accounting"
    }
  }
}
```

The `filesystems` map is caller-owned. Keys such as `jail`,
`controller-spool`, and `accounting` are Soperator profile conventions, not
Terraform module constants. Direct Terraform users can provide any logical
filesystem names that fit their workload.

### Git tag source

```hcl
module "sfs" {
  source = "git::https://github.com/nebius/nebius-ps-services.git//platform-infra/modules/sfs?ref=v0.1.0"

  parent_id      = "project-xxxxxxxx"
  name           = "client-a-prod-sfs"
  size_gib       = 500
  block_size_kib = 4
}
```

### Registry source (when published)

```hcl
module "sfs" {
  source  = "nebius/sfs/nebius"
  version = "~> 0.1"

  parent_id      = "project-xxxxxxxx"
  name           = "client-a-prod-sfs"
  size_gib       = 500
  block_size_kib = 4
}
```

## Examples

- `examples/minimal`: enabled SFS with baseline size and block size.
- `examples/named-filesystems`: caller-owned arbitrary `filesystems` map.

## Inputs summary

- Required for single-filesystem mode:
  - `parent_id`
  - `name`
  - `size_gib`
- Required for multi-filesystem mode:
  - `parent_id`
  - `filesystems`
- Filesystem controls:
  - `block_size_kib`
  - `type` (default `NETWORK_SSD`)
  - `mount_tag`
  - `forbid_deletion`
  - `filesystems`
- Runtime preconditions:
  - single mode requires non-empty `name` and `size_gib >= 1`
  - each managed `filesystems` entry requires `size_gib >= 1`
  - `existing_id` entries reference existing SFS resources instead of creating
    new filesystems

## nebius-cxcli usage

- `nebius-cxcli component add` prompts this module through
  `infra.components[].inputs`.
- `inputs.name` and `inputs.size_gib` remain the single-filesystem path.
- `inputs.filesystems` is the multi-filesystem path used by Soperator for
  `jail`, `controller-spool`, optional `accounting`, and optional jail
  submounts. Those names are cxcli profile defaults, not module-level
  hardcoding.

## Outputs summary

- `filesystem_id`
- `size_bytes`
- `mount_tag`
- `filesystems`

## nebius-cxcli mapping

For Terraform roots generated by `nebius-cxcli`, mappings are:

- `infra.sfs.name` -> `sfs_name`
- `infra.sfs.size_gib` -> `sfs_size_gib`
- `infra.sfs.block_size_kib` -> `sfs_block_size_kib`
- `infra.sfs.filesystems` -> `sfs_filesystems`
