# Implement Test

Browser runner stdout and stderr are drained incrementally. The verifier keeps
complete byte counts and hashes in bounded `runner-output.json` metadata, without
raw runner logs; assertion, screenshot and trace artifacts remain separate.
Incomplete output cannot qualify a browser phase.

The public fixture request repeats the required per-tier assignment contracts.
The coordinator must preserve concrete interfaces and constraints in the locked
task fields before dispatch; global objective text alone is insufficient.
The requested two-worker policy is configured before the first integration
allocation, which otherwise freezes defaults. The verifier never rewrites a
frozen policy to recover a failed trial.
The fixture orders database, API, frontend, then dependent integration, so the
small database task can release a slot while API work continues. Each tier
assignment declares its initially absent directory. Real native overlap and
post-admission refill remain mandatory; artificial delays cannot supply proof.
Final validation preserves each completed task's historical basis and verifies
its admission plus the owner reconciliation chain to the final specifications.
A new final spec receipt does not replace the basis under which a task ran.

Offline credential mocks use the explicit `not-a-secret` placeholder, including
environment overrides and expected-call assertions. The coordinator repeats this
constraint in affected assignments. Runtime PostgreSQL uses its declared fixture
settings, and ordinary sensitive-content screening remains required.

Execution supports Codex and Claude through the selected native host context.
See `SKILL.md` for invocation, required setup and evidence boundaries.

The companion request limits concurrency to one active worker for one task;
existing owner-authorized recovery may replace that worker while preserving
failure history and repair budgets. Its frozen Python validation commands,
including Python children launched by tests, use `-B` to avoid bytecode writes
outside exact task claims. An explicit validation environment need not inherit
the launcher's `PYTHONDONTWRITEBYTECODE`; scope guards remain unchanged.

`implement-test` is an explicit verifier for `implement`.

```text
$implement-test
$implement-test --create
$implement-test --create --keep
$implement-test --destroy
```

No flags run the Implement contract, objective/basis and continuation, and
temporary-fixture and sensitive-data regression suites plus the verifier helper, lifecycle, reporting, and
semantic suites. They do not create a real application, start Docker, or
dispatch implementation workers.
The deterministic harness collects exact test IDs before execution, runs at most
two explicitly audited independent groups, and keeps unaudited groups exclusive.
Healthy suites have no duration-only expiry. Readiness integration retains its
full traversal and real-input receipt coverage; failure blocks live preparation.

`--create` first replaces any prior exactly owned fixture, then exercises the
real Implement public interface on a seeded local-only brownfield
frontend/API/PostgreSQL project. It verifies dependency waves, worker and Git
evidence, the running application, database correlation, restart persistence,
and a canonical post-completion cross-session continuation. A lifecycle-owned
semantic gate binds those results to the generation before PASS can finish. It
writes the immutable public invocation receipt beside the native observations
in the fixture generation's `evidence/` directory, which is the same location
required by lifecycle validation. It leaves the product's run state untouched.
Native observations retain bounded failure counts and allowlisted blocker
codes. Native App Server and stream launches set a child-only `077` file mask so
worker-created private result candidates satisfy the shared owner-private file
contract. Existing results are never permission-repaired to make a failed trial
pass. The fixture therefore requires frontend, API and integration assignments
to make copied image assets readable and directories traversable by their runtime
users independently of private host modes. Offline Dockerfile checks cover the
chosen image-local permission or ownership setup; live startup and HTTP checks
remain mandatory. Neither the native umask nor host files are relaxed.
Codex additionally records at most 128 hash-only spawn and child-state
observations, including children seen before workflow task startup, plus bounded
malformed-event, overflow, interaction and sampling-gap counters. No prompts,
commands, output or arbitrary error text are retained. Missing spawn evidence
stays inconclusive, and timing never establishes a child-to-task identity.
A completed native session without an accepted objective is a failed
intake, distinct from incomplete observation; diagnostic mentions never prove
that a workflow transition occurred.
The shared-capacity oracle requires overlapping objectives and typed samples within
all three home limits: four admitted objectives, four active workers, and sixteen
retained task worktrees. Waiting objectives' retained trees still count; missing
or malformed capacity evidence fails acceptance.
It writes a sanitized report and cleans the fixture even when the test fails. The
report contains an ordered stage matrix with totals, per-stage evidence,
explicit failure analysis, downstream NOT_RUN stages, and the minimum next
action. Stage outcomes are recorded as they happen, so the cleanup/fallback
path cannot collapse a failed run into one overall sentence.
Successful cleanup preserves the corrective action for a failed live test.
Semantic validation follows each completed assignment's immutable basis through
final owner reconciliation. Coverage may fulfill unchanged statements without
new effects; each basis retains its receipt-bound plan action. Authorized worker
recoveries retain prior failures and exact native exits, with a fresh session
per attempt and no session reuse across tasks. Missing or changed proof fails.
Worker liveness is checked every 30 seconds with fresh assignment-only worker
context. Queued assignments remain unarmed until a worker slot exists; the
worker uses exact helper/workspace paths embedded in assignment v1 and passes
the embedded digest unchanged to `task-start` for authoritative validation;
it never spends the start budget guessing JSON serialization. The
verifier uses read-only `task-watch`: `QUEUED` and `PENDING_START` remain waiting
states. Stale observations, delayed startup and read-only work request diagnosis
without expiring healthy workers; unknown health retains ownership. See
[execution health](../worktree/references/execution-health.md). Successful local delivery
proceeds directly to runtime evidence and report generation.
The rendered objective leaves post-completion fresh-session continuation to
the verifier; the initial Implement turn ends after delivery and cleanup.
Before native launch, the outer verifier must measure host headroom and own an
active bounded monitor through both sessions. The controller supplies this
setup handoff to coordinators, who repeat it in assignments. The handoff alone
does not establish monitoring; unavailable outer visibility blocks launch.
Workers preserve immediate tool output/exit status and only retain a session
handle when the tool actually returns one.
The Codex launcher uses a scoped permission profile extending `:workspace`,
with writes to the isolated native home, fixture repository, exact common Git
directory and owned worktree parent. Native environment validation uses the
selected project directory, including when the verifier runs from another folder.
Its isolated config must omit legacy `sandbox_mode` and
`sandbox_workspace_write` settings, which override permission profiles.
Forcing `workspace-write` would prevent the required Git transactions.
Before each invocation, native `config/read` resolves all active layers for the
fixture. The launcher rejects effective legacy sandbox settings or changes to
the exact scoped profile; raw configuration remains in memory and is discarded.
The Codex verifier owns one foreground stdio App Server for each fresh public
invocation. It reads loaded ephemeral children with metadata-only `thread/read`
requests; it never resumes, subscribes, or reads their histories to observe them.
The refill evaluator retains native departure evidence until result admission
releases the slot. A peer must be active with the same native identity immediately
before and at admission, then continuously until a replacement starts in a later
snapshot. Authorized recovery before admission may establish that peer; a gap or
restart afterward invalidates it. Replacements first seen before or in the same
snapshot as admission cannot prove refill. Extra observations preserve valid proof.
The verifier consumes the installed owner's read-only `task-watch` status and
immutable assignment health policy. Startup, heartbeat and read-only observation
thresholds request diagnosis without expiring healthy work or releasing ownership.
Two bounded native snapshots bracket an unchanged product-state sample. Native
status/turn transitions, changed inventories, or rounds exceeding 500 ms invalidate
the sample. Read-only sampling has a bounded response window; raw protocol bytes are
hashed and discarded. Terminal failure stops immediately, and exact process-group
quiescence is required after graceful shutdown or bounded cleanup escalation.

The verifier records the owner's stale-telemetry and read-only warnings and
rejects autonomous or background heartbeat loops.
It also rejects replayed `task-start` and out-of-claim mutations as liveness
progress.
Generated Compose is treated as untrusted: an exact pre-Compose allowlist
rejects external file and unsafe build features, while locally built images
must carry exact generation and verifier-project labels. Service network
attachments must use long-form object-map syntax with empty option objects;
list syntax fails before Docker runs. Application mutation
and evidence collection hold one generation lease through restart verification.
Before HTTP checks and after the API restart, the collector requires exactly
one running container for each required service, healthy when a healthcheck is
configured. It waits up to 60 seconds only for startup health, including Docker
inspection time; failed services, late results or invalid inventories fail.
Imported and direct CLI execution share bounded lifecycle errors.
The canonical-model pass accepts Docker Compose's injected null `command` and
`entrypoint` defaults and empty network `ipam` default only after the raw source
pass has proved those keys were not authored; any non-null runtime or non-empty
IPAM override remains rejected.

`--create --keep` performs the same replacement and verification but retains
the one current owned application, private verifier state, and runtime for
inspection. A later `--destroy` removes only that recorded owned generation;
repeating destroy returns `ALREADY_DESTROYED`.
Filesystem cleanup atomically moves the run behind a recoverable deleting
pointer, so an interrupted or partially failed recursive deletion resumes only
that exact tombstone without trying to re-adopt a damaged project.

Create never blindly overwrites a directory. It performs an ownership-checked
destroy-and-replace under the canonical private root. A symlink, wrong marker,
remote, external linked worktree, stale generation, or ambiguous Docker
resource blocks replacement so a second instance is never created. Because
the kept app is disposable, explicit destroy or the next create removes edits
inside that exact owned run.

The deterministic profile covers shared Implement reporting and transition overhead.
Live semantic admission requires immutable initial architecture before bootstrap,
recorded execution and final delivery reports. Sanitized Markdown/JSON survives
cleanup in the generation archive. Fresh Playwright UAT is a separate stage from
HTTP/API/database checks; missing reporting or browser evidence remains partial.
Only lifecycle `validate-results` records workflow-statistics PASS. Generic
`record-stage` rejects that success before mutation, preserving the stage for
canonical semantic admission and avoiding conflicting immutable report details.

The Implement verifier freezes a successful deterministic preflight and physical
installed dependency catalog for each fresh `--create` trial. Its lifecycle owns
Playwright UI, API/database correlation, restart and browser cleanup evidence;
prose cannot satisfy browser acceptance. Root ownership and active generation
versions are checked separately, and observed native failures remain FAIL.
