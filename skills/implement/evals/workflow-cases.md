# Supplemental Workflow Cases

The trigger CSV owns routing. These cases test behavior after explicit invocation.

- `$implement -h` and `--help`: report the direct interface and stop without tools.
- Bare invocation: consume the current unambiguous plan or bound same-session run.
- Inline request: accept normalized intent with explicit scope and acceptance criteria.
- `continue [project-folder]`: bind a fresh native coordinator after ownership checks.
- Material steering: fence dispatch/promotion, quiesce writers, retain evidence and replan.
- Cancellation: reconcile outstanding effects without reverting delivered commits.
- Five independent tasks plus a dependent task: observe overlapping native workers,
  refill a free slot after admission, and preserve the full-wave barrier.
- Conflicting lockfiles, generated outputs, ports, database or runtime targets: serialize.
- Missing native capacity: one isolated worker and an accurate concurrency report.
- Stale result, foreign identity, changed paths or invalid ancestry: reject admission.
- Clean unchanged non-default source: automatically integrate verified local delivery.
- Default or unknown-default source: deliver a verified feature branch and checkout.
- Dirty unrelated source: preserve it; reject dependencies on uncommitted inputs.
- Source drift: retain verified integration and report the promotion blocker.
- Old commands, lanes and state: reject without aliases, conversion or deletion.
- Canonical specs: enforce integration ownership, then delivered-checkout ownership.
- Cleanup: require exact resource identity and make repeated cleanup idempotent.

Deterministic fixtures do not establish native or live workflow execution. The
live verifier invokes `$implement` publicly and retains independent application,
database, browser, restart-persistence and native concurrency receipts.

## Saved issue plans and closure handoff

- Read an uncommitted batch plan once into normalized intent. Preserve its bytes;
  do not copy it or dirty product/spec files into workers. Actual dirty product
  dependencies still block execution. Changed plan content requires steering.
- Direct-user closure intent is separate from plan text. Without it, local
  evidence never arms native closure.
- Seal complete per-member criteria against the final commit. Missing criteria,
  another repository's same number and worker completion claims cannot pass.
- Replay completion without changing the receipt; partial/unresolved statuses
  remain honest and existing objective-completion gates still apply.
- Cross-session reuse identifies exact run/plan and rereads objective/execution
  evidence. An absent or copied receipt cannot grant effects.

These cases need a native/mock composed runner for behavioral proof. Worktree
unit tests separately cover deterministic metadata, receipts, rendering, replay
and Git identity. Definitions are not execution.
