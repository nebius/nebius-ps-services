# Base Layout

Use this baseline for every scaffold unless the user requests a different structure.

## Repository Tree

```text
.
├── README.md
├── CHANGELOG.md
├── LICENSE
├── .gitignore
├── .python-version          # optional; pin when repo policy requires it
├── pyproject.toml
├── uv.lock                  # generated by uv; commit, review, never hand-edit
├── Makefile
├── .pre-commit-config.yaml
├── .github/
│   └── workflows/
│       └── ci.yml
├── src/
│   └── <package_name>/
│       ├── __init__.py
│       ├── __main__.py
│       ├── cli.py
│       ├── settings.py
│       ├── logging.py
│       ├── runtime_version.py   # source/install version resolver
│       └── _version.py   # generated by setuptools-scm
├── tests/
│   ├── conftest.py
│   ├── unit/
│   │   ├── test_cli.py
│   │   └── test_config.py
│   ├── integration/         # only meaningful real collaboration
│   ├── contract/            # optional, offline interfaces
│   └── e2e/                 # optional, complete workflows
├── scripts/
│   ├── dev.sh
│   └── smoke-wheel.py       # packaging/automation profile
└── infra/
    └── terraform/
```

Remove optional directories only if they are out of scope.

When `systemd` is selected, add the source module named by the unit's explicit
fully qualified service-module value. Do not assume a fixed `agent.main` path.

## pyproject.toml Baseline

Use `assets/pyproject.toml.template` and replace placeholders.

Key points:

- Use PEP 621 metadata under `[project]`.
- Default to `setuptools` build backend.
- Use `setuptools-scm` for dynamic versioning from Git tags.
- If the package exposes `__version__`, prefer a runtime resolver that checks
  live SCM state first in source/editable checkouts instead of importing the
  generated `_version.py` directly.
- Keep runtime and dev dependencies separate.
- Put development tools in `[dependency-groups].dev`.
- Add `[project.optional-dependencies]` only for consumer-selectable extras;
  required profile dependencies belong in `[project].dependencies`.
- Generate and commit `uv.lock`; do not create it from a template.

## .gitignore Baseline

Include at least:

- Python artifacts: `__pycache__/`, `*.py[cod]`, `.pytest_cache/`, `.ruff_cache/`, `.mypy_cache/`
- Virtual envs: `.venv/`, `venv/`, `.env/`
- Build artifacts: `build/`, `dist/`, `*.egg-info/`
- Local/secrets patterns: `*.env`, `*.local.*`, `*.key`, `*.pem`, `*.token`, `*.secret`
- Tool output: `.coverage*`, `htmlcov/`, `.tox/`, `.nox/`

Never ignore source folders broadly.

## Commands And Testing

Use `references/testing.md` and the Makefile asset as the single testing authority.
Run `uv lock --check`, `uv sync --locked`, then `make check` for fast validation,
`make coverage` for full non-external coverage and `make smoke-wheel` to prove the
installed artifact. `make build` retains distributable output.

Keep `.DEFAULT_GOAL := all` and `all: check smoke-wheel`. Optional layer and smoke
targets exist only with meaningful tests; no blanket no-tests-collected exception.
Classify by behavior rather than filesystem use or execution speed. Unit CLI
parsing examples stay in unit tests; real workflows receive separate E2E proof.
