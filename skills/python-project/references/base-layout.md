# Base Layout

Use this baseline for every scaffold unless the user requests a different structure.

## Repository Tree

```text
.
├── README.md
├── CHANGELOG.md
├── LICENSE
├── .gitignore
├── .python-version          # optional; pin when repo policy requires it
├── pyproject.toml
├── uv.lock                  # generated by uv; commit, review, never hand-edit
├── Makefile
├── .pre-commit-config.yaml
├── .github/
│   └── workflows/
│       └── ci.yml
├── src/
│   └── <package_name>/
│       ├── __init__.py
│       ├── __main__.py
│       ├── cli.py
│       ├── settings.py
│       ├── logging.py
│       ├── runtime_version.py   # source/install version resolver
│       └── _version.py   # generated by setuptools-scm
├── tests/
│   ├── conftest.py
│   ├── unit/
│   │   ├── test_cli.py
│   │   └── test_smoke.py
│   └── integration/
│       └── test_cli_smoke.py
├── scripts/
│   └── dev.sh
└── infra/
    └── terraform/
```

Remove optional directories only if they are out of scope.

When `systemd` is selected, add the source module named by the unit's explicit
fully qualified service-module value. Do not assume a fixed `agent.main` path.

## pyproject.toml Baseline

Use `assets/pyproject.toml.template` and replace placeholders.

Key points:

- Use PEP 621 metadata under `[project]`.
- Default to `setuptools` build backend.
- Use `setuptools-scm` for dynamic versioning from Git tags.
- If the package exposes `__version__`, prefer a runtime resolver that checks
  live SCM state first in source/editable checkouts instead of importing the
  generated `_version.py` directly.
- Keep runtime and dev dependencies separate.
- Put development tools in `[dependency-groups].dev`.
- Add `[project.optional-dependencies]` only for consumer-selectable extras;
  required profile dependencies belong in `[project].dependencies`.
- Generate and commit `uv.lock`; do not create it from a template.

## .gitignore Baseline

Include at least:

- Python artifacts: `__pycache__/`, `*.py[cod]`, `.pytest_cache/`, `.ruff_cache/`, `.mypy_cache/`
- Virtual envs: `.venv/`, `venv/`, `.env/`
- Build artifacts: `build/`, `dist/`, `*.egg-info/`
- Local/secrets patterns: `*.env`, `*.local.*`, `*.key`, `*.pem`, `*.token`, `*.secret`
- Tool output: `.coverage*`, `htmlcov/`, `.tox/`, `.nox/`

Never ignore source folders broadly.

## Recommended Commands

```bash
uv self version
uv lock --check
uv sync --locked
uv run --locked ruff check src tests
uv run --locked pytest -m "not integration" tests/unit
uv run --locked pytest -m integration tests/integration
uv run --locked python -m build --wheel
```

## Makefile Targets

At minimum:

- `.DEFAULT_GOAL := all`
- `all`: aggregate target, typically `check + build`
- `lock-check`: `uv lock --check`
- `sync`: `uv sync --locked`
- `fmt`: `uv run --locked ruff format`
- `lint`: `uv run --locked ruff check`
- `test`: alias to fast unit tests
- `test-unit`: `uv run --locked pytest -m "not integration" tests/unit`
- `test-integration`: `uv run --locked pytest -m integration tests/integration`
- `coverage`: `uv run --locked pytest --cov=<package_name> tests/unit`
- `build`: `uv run --locked python -m build --wheel`
- `check`: `lint + test-unit`

## Testing Baseline

- Default to split test lanes:
  - `tests/unit/` for fast local development.
  - `tests/integration/` for isolated smoke/integration checks.
- Add an autouse fixture in `tests/conftest.py` that blocks network access for unit tests.
- Keep unit tests focused on pure logic, validation, rendering, and CLI parsing.
- Patch external APIs, cloud clients, and subprocess boundaries in unit tests.
- Add one CLI smoke test for each user-facing command group when CLI is in scope.
- Add one config/schema validation test with realistic sample input when typed config exists.
- Fail fast in CI for lint and unit tests before packaging.
